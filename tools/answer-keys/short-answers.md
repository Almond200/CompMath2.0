# Official short-answer keys

`js/data/problems/answer-keys-short.js` contains answers verified against official keys, worked solutions, or independent calculations. The `sources` map records the official solution URL or the problem paper used for independent verification. The paper ID is the problem slug without its final problem number. The import matches numbered questions in the source PDFs to the app’s slugs and checks against local statements. Plain numeric answers can be extracted from the labeled answer in a PDF. Stacked fractions, radicals, and questions with more than one answer need particular care because PDF text extraction can drop signs, fraction bars, and exponents.

Each entry contains an `answers` array of fully correct submissions. Its default format is a single real value. Use `format: "set"` for an unordered list of values, `"sequence"` for a list that must follow a specified order, `"tuple"` for one parenthesized ordered tuple, and `"tuple-set"` for an unordered list of ordered tuples. Put a complete list in one string, such as `["4, 6"]`. For a prompt asking for any one acceptable answer, use a separate array entry for each accepted alternative. Keep the multiple-choice imports in their own files.

Use plain math expressions in the keys. The answer field accepts fractions, mixed numbers such as `-1 1/2`, `sqrt(3)`, `cbrt(2)`, `pi`, powers, factorials, binomial coefficients such as `choose(2019,3)`, `ln`, and the `sin`, `cos`, and `tan` functions. Separate entries with a comma. Spaces are optional. Exact rational keys require exact equality. The checker reduces fractions, proves common root and trigonometric identities, and cancels equal terms and nonzero factors before evaluation. A small numerical tolerance still applies to keys that evaluate numerically. Questions with an unverified key or an unsupported answer form stay available for self-check. Saved self-check sets keep their existing marks.

Set `external: true` when the problem is read from the original paper and the app has a verified key. Practice links to the paper and grades the response from the key.

Use `"percent"` when the official answer is expressed as a percentage. The player can include or omit the percent symbol. Use `"text"` for short answers such as a day of the week or digits in a specified base. List acceptable forms explicitly. Text matching ignores case and extra spaces.

Use `"complex"` for one complex number and `"complex-set"` for all complex numbers. The player can use `i`, common arithmetic operations, integer powers, and `sqrt(z)` for the principal square root. Integer powers of `i` use its four-value cycle. Other complex powers accept integer exponents from −64 to 64. Real and imaginary components are compared separately. For example, `0, ±i*sqrt(6)` stands for all three values in 2024 HMMT February Algebra and Number Theory #9.

Use `fib(n)` for an exact Fibonacci number with \(F_0=0\) and \(F_1=1\). A key can set `notation: "fibonacci"` to accept `F_n` in the context of that problem. The published answer to 2020 CMIMC Combinatorics and Computer Science #8 can be entered as `(100, F_104+1223)` or `(100, fib(104)+1223)`. [Official solutions](https://github.com/howard36/cmimc-official/blob/master/public/assets/docs/past-tests/2020_CCS_S.pdf)

Use `"interval"` for a real interval or union. The checker accepts bracket notation and inequalities such as `[38,88)` and `38 <= x < 88`. An unbounded endpoint can use `inf` or `infinity`. Separate disjoint intervals with `U` or `or`. Open and closed endpoints affect the grade.

Use `"polynomial"` with the variable in `notation`. The checker compares exact rational coefficients through degree 32. For example, `n(n+5)-3` and `n^2+5n-3` both work for 2006 Lehigh #30. Use `notation: "ratio"` on a single real value when the prompt asks for a ratio. Students can enter `4:6` or `2/3` for the same ratio.

Practice saves and typesets symbolic entries such as `y=2x` and `A_{104}/z`. The answer key's format still determines whether the entry earns credit.

Use `"rational-function"` with a single variable in `notation` for a quotient of polynomials. The checker compares the cross-products by exact coefficients, so it compares formulas on their common domain. The 2009 Duke Math Meet #2 key accepts `2/n`, `2*n^-1`, and `1/n+1/n`.

Use `notation: "angle"` for keys in radians that also accept an explicit degree unit. The 2025 SMT Algebra #8 key accepts `29pi/12`, `435°`, and `435 deg`. For the fixed units recorded in the key, students can include the unit or enter the number alone. This includes `9 points` in 2009 Duke Math Meet #3, `145 inches` in 2013 BmMT #14, and `184 sq in` in 2009 Lehigh #27.

Use `notation: "repeating-decimal"` when the published answer includes a recurring decimal. For 2019 BMT Discrete Math #2, `0.(18)` and `0.\overline{18}` both represent exactly `2/11`. A finite decimal is compared by its exact value. [Official solutions](https://berkeley.mt/archives/bmt-2019/discrete-solutions.pdf)

Use `format: "tuple", notation: "polar"` for a radius and angle. The checker accepts coterminal angles, including degrees with `°` or `deg`. Use `notation: "profit"` on a signed real key when the question asks for a gain or loss. Both `-40` and `40 loss` express the same loss.

Use `format: "percent", notation: "percent-change"` when a question asks for the direction of a percentage change. For a decrease, `-9%`, `decreases by 9%`, and `9% decrease` all express the same answer.

Use `format: "sequence", notation: "base-3"` when a prompt requests ternary digit strings in order. Students can enter digits with an optional `_3`, `_{3}`, or `₃` suffix. The preview includes the base subscript.

Every typed Practice answer uses the same Math keypad. AIME still grades integers from 0 through 999, including expressions that evaluate to those values and entries with leading zeros such as `007`.

Read the submission instruction in the problem and inspect the typeset official answer when the PDF extraction is ambiguous. Check what a subscript denotes before selecting a format. A Fibonacci number, a digit string in a specified base, and an indexed variable require different handling. Record any notation that still needs a verifier with the problem number and source.

If a key and its solution disagree, first match the question to the original sitting. Check the PDF, any organizer correction, and an independent calculation before changing the accepted value. Record the published and corrected answers with the source. Log unusually large exact values along with the relevant limits of the grader so their support can be decided from the actual problem.
